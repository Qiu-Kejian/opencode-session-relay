# 架构设计

`opencode-session-relay` 的核心目标：**让一条接力链内的会话在连续工作时"零压缩劣化"。**

## 1. 要解决的问题

LLM 助手（如 OpenCode）上下文有上限。会话过长触发**压缩（compaction）**时会生成摘要续跑，但摘要会丢失细节、让任务背景失真。本插件在最痛的时点——会话即将压缩前——截获它，改为**交接**：

- 把关键上下文落成一份**交接文书**（Markdown 文件）
- （可选自动）创建一个**新会话**继续
- 用**接力链标识 `SR-xxxxxxxx`** 把后续会话串成一条链，链内继续交接就不再询问

结果：同一条链内的工作在完整、未劣化（未压缩）的上下文中连续推进。

## 2. 核心概念

| 概念 | 说明 |
|------|------|
| **接力链 (chain)** | 一条连续工作的完整语义单元，标识 `SR-xxxxxxxx`（8 位 hex）。链内所有会话自动接力。 |
| **跳 (hop/docNumber)** | 链内每次交接为「一跳」，产生一份文书，序号从 1 递增。 |
| **归链 (sessionChain)** | 会话 → 链的映射。归链后的会话压缩走「自动交接」，不再询问。 |
| **决策 (denoise)** | 未归链会话压缩前提示「交接 / 压缩」；同会话首次强提醒，之后轻提醒。 |

## 3. 数据模型

状态文件：`{项目根}/{handoffDir}/.relay-state.json`

```jsonc
{
  "chains": {
    "SR-xxxxxxxx": {
      "docs": [".../SR-xxxxxxxx-20260827-交接-1.md"],   // 历史文书路径索引（每跳一份）
      "sessions": ["ses_..."],                              // 归链会话 ID 列表
      "used": ["ses_..."]                                  // 已完成交接的会话（不重复交接）
    }
  },
  "sessionChain": { "ses_...": "SR-xxxxxxxx" },           // 会话 → 链 映射
  "counts": { "ses_...": 2 },                            // 各会话压缩次数
  "reminded": ["ses_..."]                                  // 已做过首次强提醒的会话
}
```

## 4. 事件/钩子处理

插件实现了三类入口：

| 入口 | 触发时机 | 职责 |
|------|---------|------|
| `event` (`session.compacted`) | 会话实际压缩完成 | 累加 `counts` |
| `chat.message` | 用户消息 | 归链（携带 `SR-xxx` token）/ 显式进入接力 / `@relay` 命令 |
| `experimental.session.compacting` | 会话即将压缩 | 决策提示 or 执行全自动交接 |

## 5. 关键设计决策（ADR 精简）

### ADR-1 用接力链标识做路由，而非全局/按项目
- **问题**：如何识别"新会话应接哪条链"？
- **选择**：在交接语义内嵌 `SR-xxxxxxxx`；新会话首条消息含该 token → 插件据此归链。
- **理由**：纯插件侧唯一可靠的跨会话路由信号；链间互不影响，可从各自压缩节点独立进入交接。

### ADR-2 全自动交接 = create + 注入，含时序握手
- **问题**：新会话如何读到"还没写出的交接文书"？
- **选择**：`client.session.create` 建接力会话 → `client.session.prompt` 注入首条消息，指令明确"先 sleep 15s，每 10s 重试最多 5 次"。
- **理由**：文书由当前会话模型在 `compacting` 过程中才落盘，注入时尚未生成；用显式重试窗口而非裸轮询，靠新会话模型自觉等待。

### ADR-3 部分失败分离（不留幽灵会话）
- **问题**：create 成功但注入失败，或 create 失败？
- **选择**：
  - create 失败 → 完整降级**半自动**（输出可复制交接语），不建会话。
  - create 成功 + 注入失败 → **保留已建会话** + warning 提示，不产生重复会话。
- **理由**：避免"建了会话却空转"或"提示用户再建一个"的矛盾。

### ADR-4 交接文书路径确定性
- **问题**：插件事先不知道文书最终路径，无法在注入时告诉新会话读哪个文件。
- **选择**：插件**接管路径命名**为 `{链标识}-{日期}-交接-{n}.md`（`n` 由 `docs.length+1` 确定性算出），`relayPrompt` 命令当前会话"必须写入该精确路径"。
- **理由**：新旧会话引用的路径完全一致，消除歧义。

### ADR-5 零硬编码 / 跨平台
- 路径一律用 `join()`；接链标识与触发词可配；不依赖具体项目目录。使包可通用发布。

## 6. 可靠性

- 状态读写单文件，`loadState` 损坏时安全重置。
- 所有入口 `try/catch`；异常双通道（`client.app.log`/console + toast）。
- 依赖 `ctx.config` 提供默认值 + 可覆盖。

## 7. 可扩展点

- 自定义交接模板：改 `index.js` 结尾的 `relayPrompt` 系列函数。
- 新触发词：`config.enterRegex` / `config.compactRegex`。
- 自定义交接目录：`config.handoffDir`。
